### Concrete risks

1. **Scheduling gates ignored.** `pod.Spec.SchedulingGates` is never read; a gated pod (Kueue, Volcano, any queueing controller) gets the full capacity analysis and can be reported as a fragmentation Blocker or "should fit" (analyze.go:117-377). Why it matters: the scheduler has not looked at the pod at all, so every cause emitted is fabricated and exit code 1 is a false alarm.

2. **Preemption invisible.** `pod.Status.NominatedNodeName` is never consulted; a high-priority pod mid-preemption is reported as "Insufficient free capacity" Blocker (analyze.go:317-327). Why it matters: the scheduler is actively fixing it; the tool tells the user to add nodes.

3. **Pod affinity self-match exception missing.** The scheduler allows a pod whose required affinity term matches its own labels when no other pod matches (first replica of "co-locate with app=web"). topology.go:189 emits a Blocker instead. Why it matters: this is the most common required-affinity shape in Deployments; it fires on every fresh rollout.

4. **Affinity/anti-affinity only see pods on eligible nodes.** `nodeByName` is built from `eligible` only (topology.go:164-171), so a matching pod on a tainted or full node in the same zone is invisible. Why it matters: zone-scoped affinity gives a false "unsatisfied" Blocker; zone-scoped anti-affinity gives a false "should fit".

5. **`namespaceSelector` ignored.** Only `t.Namespaces` is honored (topology.go:155-159); `namespaceSelector: {}` (all namespaces) is treated as the pod's own namespace. Why it matters: silent wrong scope for cross-namespace affinity.

6. **Symmetric anti-affinity not modeled.** `PlacedPod` carries only labels (topology.go:13-17, main.go:292-296), so an existing pod's required anti-affinity against the incoming pod is never checked. Why it matters: the scheduler enforces both directions; the tool says "should fit".

7. **Topology spread domain set diverges from the scheduler.** Domains are enumerated from `allNodes` including nodes that fail nodeSelector/nodeAffinity (topology.go:86-98); with the default `nodeAffinityPolicy: Honor` the scheduler excludes those. Why it matters: a zone reachable only by non-matching nodes drives `globalMin` to 0 and produces a false "can't be satisfied" Blocker. Terminating pods (DeletionTimestamp) are also counted; the scheduler skips them.

8. **Empty NodeSelectorTerm matches everything here, nothing in Kubernetes.** `matchTerm` returns true for a term with no expressions/fields (predicates.go:103-120). Why it matters: small on its own, but it is symptomatic of reimplementing `k8s.io/component-helpers/scheduling/corev1` by hand (see Code Health).

9. **NodeResourcesFit under-counts.** `PodRequests` omits `pod.Spec.Overhead` (RuntimeClass overhead for kata/gVisor), treats native sidecar init containers (`restartPolicy: Always`) as max instead of sum (resources.go:44-59), excludes ephemeral-storage entirely (resources.go:20-26, never compared to allocatable), and ignores pod-level resources. Why it matters: the tool prints "fits" while the scheduler says Insufficient; overhead alone is a fixed per-pod delta on every sandboxed cluster.

10. **NotReady and cordon modeled as hard filters, scheduler uses taints.** `IsReady` returns false when the Ready condition is absent (predicates.go:15-22) and NotReady/cordoned nodes are excluded unconditionally (analyze.go:157-165), but the scheduler filters via `node.kubernetes.io/not-ready` and `node.kubernetes.io/unschedulable` taints that DaemonSet-style pods tolerate. Why it matters: infra pods with those tolerations get a false Blocker.

11. **Per-node verdict is frozen before cross-pod and extended analyses run.** A node gets `Schedulable: true, "fits (CPU/memory)"` at analyze.go:214 and is never updated by `AnalyzeExtendedResources`, `AnalyzeTopologySpread`, `AnalyzePodAffinity`, or `AnalyzeDRA` (analyze.go:331-349). Why it matters: `-o json` reports `schedulable: true` for a node that cannot host the pod, on the feature README.md:121-145 sells as the differentiator.

12. **Volume handling is the weakest area for the stated on-prem niche.** Any non-Bound PVC is a Blocker (analyze.go:135-142) including WaitForFirstConsumer PVCs whose Pending state is normal (the StorageClass `volumeBindingMode` is never read); ephemeral volumes' generated PVCs (`<pod>-<volume>`) are skipped because only `PersistentVolumeClaim` sources are checked (main.go:390-394); and a Bound local PV's `nodeAffinity` (local-path, OpenEBS, TopoLVM) is never checked, so a pod pinned to a full node is misattributed. Why it matters: local PV pinning is the single most common bare-metal storage cause; WFFC gives exit 1 and a Blocker that buries the real cause.

13. **hostPort conflicts not modeled.** No port data in `PlacedPod`; NodePorts plugin absent. Why it matters: ingress controllers and DaemonSets with hostPort are standard on bare metal; the tool says "should fit".

14. **DRA gather turns read errors into a confident wrong Blocker.** `gatherDRA` swallows all errors (main.go:321-329): RBAC Forbidden, or a 1.32/1.33 cluster serving only `resource.k8s.io/v1beta1`/`v1beta2`, yields nil claims, and `AnalyzeDRA` then emits "ResourceClaim not found" as a Blocker (dra.go:74-83). Claims are also listed cluster-wide (`ResourceClaims("")`, main.go:321), which namespace-scoped users cannot do. Only DeviceTaintRules get the v1beta2 fallback (main.go:337-361). Why it matters: an unreadable API becomes "your claim doesn't exist".

15. **DRA allocation reasoning is a guess.** Devices are counted cluster-wide with no mapping from ResourceSlice `nodeName`/`nodeSelector`/`allNodes` to the nodes the pod can reach; other claims' `status.allocation` are never summed, so "likely all already in use" (dra.go:138) is literal guesswork; `Exactly.Count`, `allocationMode: All`, `adminAccess`, partitionable devices/counters, DeviceClass `selectors`, and DRA-backed extended resources (1.34+ alpha, would be flagged "no node provides") are all absent. Why it matters: GPUs are the headline use case.

16. **Scheduler event may never render.** `latestSchedulerEvent` picks by `LastTimestamp` only (main.go:380-384). The scheduler records through `events.k8s.io/v1`, whose core/v1 projection carries `eventTime` and `series.lastObservedTime` with `lastTimestamp` often zero; `ts.After(latest)` is then never true and `msg` stays empty. kubectl's printer falls back to those fields for exactly this reason. The field selector also lacks `involvedObject.uid`, so a recreated same-named pod (StatefulSet) inherits stale events. Why it matters: README.md:87 promises the raw scheduler event as the fallback; coverage of this function is 37.5% and no test exercises it.

17. **Watch-cache pagination is not guaranteed.** main.go:227-231 and 267 claim memory bounded by page size, but a LIST with `ResourceVersion: "0"` is served from the watch cache, which historically ignores `limit` and returns the whole list unless ListFromCacheSnapshot (beta in 1.34) is active; client-go's pager also falls back to an unpaged full list on 410 (pager.go:114-120). The scale test fakes pagination client-side (main_scale_test.go:103-121). Why it matters: the acceptance criterion in docs/issues/large-cluster-scaling.md:47-48 is only met on new clusters, and nobody has observed it against a real apiserver.

18. **Single hard-coded 30s deadline for the whole run.** main.go:93 covers node list, all pod pages, and per-pending-pod Events LISTs plus PVC GETs done sequentially (main.go:120-137; Events field-selector lists are etcd reads, not cache reads). Why it matters: `-A` with a few hundred pending batch pods, or a 100k-pod cluster, exits 3 with "context deadline exceeded" and no partial output; there is no flag to raise it.

19. **Cluster-wide RBAC required, undocumented, opaque on failure.** `Nodes().List` and `Pods("").List` (main.go:233, 239) need cluster-scope list; Forbidden exits 3 with the raw error. Why it matters: the developer who can `kubectl describe pod` in their namespace cannot run this at all, and the README never says so.

20. **"No Pending pods found" printed for pods that are Pending.** A Pending pod with `spec.nodeName` set returns `nil, nil` (main.go:194-200) and `run` then prints the success line with the party emoji (main.go:100-109); in `-A` mode such pods are dropped silently (main.go:213). Why it matters: ContainerCreating / image pull / volume attach pods show as Pending in `kubectl get pods`; users get a false all-clear.

21. **First-failure attribution.** The node loop stops at the first failing predicate (analyze.go:154-227), so "3/4 nodes don't match nodeSelector" depends on check order and a fix like "remove the taint" can be suggested for a node that also fails the selector. Why it matters: the scheduler reports every failing plugin per node; the tool's counts are order artifacts.

22. **Multi-arch, Windows, virtual kubelet.** No OS/arch awareness (not scheduler filters, but a Linux pod gets `fits` on a Windows node at analyze.go:214); a tolerated virtual-kubelet node with huge allocatable dominates `maxAlloc`/`sumFree` (analyze.go:189-209) and hides fragmentation; a Ready node with empty allocatable produces "larger than any single node" (analyze.go:294). Why it matters: low frequency, but all three are wrong-not-crashing.

23. **Units.** `Resources.Extended` mixes counts and bytes; extended.go:50 and operator.go:167 print raw ints, so hugepages renders as "2097152 of hugepages-2Mi". `FormatMem` prints "0B". Why it matters: cosmetic, but it reads as a bug to users.

24. **No crash paths found.** Every pointer deref is guarded (predicates.go:88-94, dra.go:24-31, main.go:349, `e.Values[0]` at predicates.go:138). `int32` conversion at topology.go:127 is safe. The fake-clientset e2e test would surface most nil panics. This is a genuine strength.

## 2. USABILITY GAPS

1. **Hand-rolled flag parser rejects `--flag=value`.** `--namespace=foo` and `-n=foo` hit "unknown flag" (args.go:38). Why it matters: every kubectl user types that form.

2. **No cli-runtime.** `k8s.io/cli-runtime` is not in go.mod; no `--as`, `--as-group`, `--server`, `--token`, `--user`, `--cluster`, `--insecure-skip-tls-verify`, `--request-timeout`, `-v`. Why it matters: impersonation is how platform teams debug user namespaces; `--request-timeout` is the standard fix for item 18.

3. **No `--version`.** args.go has none; Makefile:35 stamps no ldflags. Why it matters: krew users filing misdiagnosis issues (the template you ship) cannot say which build they ran.

4. **Per-node verdicts never appear in text mode.** report.go:38-64 prints causes and the event only; `Result.Nodes` is json/yaml-only. Why it matters: "which node was filtered by what" is the fastest thing to read on a 5-node cluster.

5. **No grouping for many pending pods.** `run` prints one full block per pod (main.go:145-147); 500 pending Job pods yield 500 identical fragmentation reports. Why it matters: `-A` on a busy cluster is unreadable; a "N pods share cause X" summary is the obvious shape.

6. **Nothing for not-yet-created pods.** No `-f pod.yaml` dry-run against current cluster state, and no Deployment/Job/StatefulSet mode that explains zero replicas (ResourceQuota exceeded, LimitRange rejection, admission webhook, PodSecurity, PVC template). Why it matters: "why isn't my Deployment creating pods" is the sibling question users will ask this tool.

7. **Pending-with-node pods get "nothing to diagnose".** See risk 20; the tool could at least print the container waiting reason. Why it matters: it is the same word in `kubectl get pods`.

8. **Fix suggestions are templates, not commands.** Node names are known but the text says `kubectl taint nodes <node> <key>-` (analyze.go:257), `kubectl label node <node> key=value` (analyze.go:266), `kubectl uncordon <node>` (analyze.go:284). Why it matters: a copy-pasteable command with the real node and taint is the whole promise of "get the fix".

9. **Stale fallback wording.** analyze.go:359-360 tells the user to check `kubectl describe pod` for topology-spread or pod-affinity constraints that the tool now models itself. Why it matters: undermines trust in the diagnosis.

10. **Exit code cannot distinguish "pending, cause unknown".** Info-only results exit 0 (main.go:150-157). Why it matters: `kubectl why-pending -A -o json || alert` (README.md:149) stays silent for a pod stuck for hours on an unmodeled cause.

11. **No `--watch`** (README.md:162 roadmap). Why it matters: pending is a transient state; the interesting question is "what changed when it scheduled".

12. **No Windows build.** Makefile:28 and .krew.yaml platforms omit windows/amd64, which krew supports. Text output also hard-codes non-ASCII glyphs (analyze.go:22-31, report.go:46, main.go:108) with no `--ascii`. Why it matters: excludes a platform and complicates log shipping.

13. **What works well.** Standalone binary and kubectl plugin both work (plain `main`, no kubectl dependency); in-cluster config falls back correctly through the deferred loading config (main.go:169); `NO_COLOR` plus TTY detection (report.go:20-29); json/yaml always emit an array (serialize.go:17-18); usage text and README exit codes agree.

## 3. CODE HEALTH

1. **Zero-coverage functions.** `parseArgs` (args.go:10), `newClient` (main.go:160), the entire nodeAffinity engine `matchTerm`/`matchExpr`/`matchExprValue` (predicates.go:103-152, 0%), `Severity.Icon`, `ChainRelevant` within its own package. Low: `unboundPVCs` 22% (missing-vs-RBAC branch untested), `latestSchedulerEvent` 37.5%, `pendingPods` 45.5%, `emit` yaml branch, `tolerationTolerates` 53.8% (empty-key Exists wildcard, NoExecute, PreferNoSchedule untested). Why it matters: the predicate code that decides eligibility is the least tested code in the repo.

2. **No predicates_test.go, no report test, no args test.** report.go writes through `fmt.Println` to stdout with no `io.Writer` injection, so text output has never been asserted (main_test.go:68-80 checks only `blockers == true`). Why it matters: the README's sample output can drift from reality with a green CI.

3. **Fake-clientset integration exists but is shallow.** main_test.go:56 drives `run()` through `fake.NewSimpleClientset` (deprecated in favor of `fake.NewClientset`). The fake ignores field selectors, so the `status.phase=Pending` filter (main.go:204) is never exercised and is masked by the client-side recheck; the fake never returns `Continue`, so real pagination is only tested through the hand-written listFn. Why it matters: gather-path behavior against a real apiserver is unverified; a kind-based or envtest smoke test would close this.

4. **Untested DRA/topology branches.** Template resolution via `status.resourceClaimStatuses` (dra.go:27-31), missing topology key (topology.go:99-107), `Namespaces` on affinity terms, `ScheduleAnyway` skip. Why it matters: these are the branches most likely to see real-cluster input shapes.

5. **Reimplementing component-helpers.** predicates.go reimplements `corev1helpers.TolerationsTolerateTaint` and `nodeaffinity.NewNodeSelector`; topology.go:22-53 reimplements `metav1.LabelSelectorAsSelector`. Risk 8 is the first divergence. Why it matters: `k8s.io/component-helpers` is a small dependency already consistent with the scheduler by construction.

6. **Duplication.** `tolerationTolerates` (predicates.go:50-71) and `deviceTolerationTolerates` (devicetaints.go:95-116) are the same algorithm; `contains`/`keys` (predicates.go:154, analyze.go:390) duplicate `slices.Contains`/`slices.Sorted(maps.Keys())` on a go 1.26 module; `Allocatable(node)` is recomputed inside the per-resource loop (extended.go:32); `nodeByName` is rebuilt per constraint and per term (topology.go:83, 164). Why it matters: minor, but the per-pod recomputation is O(pending x nodes x resources) on `-A`.

7. **Adding a predicate is harder than CONTRIBUTING suggests.** `Analyze` is a 260-line function (analyze.go:117-377) with the node loop, `counts` map, `NodeVerdict`, and cause emission hand-wired; there is no `Filter` interface, and post-loop analyses cannot update verdicts. Adding NodePorts touches `PlacedPod`, `streamPods`, `Analyze`, and the verdict. CONTRIBUTING.md:48-56 omits updating `NodeVerdict` and the Info fallback text. Why it matters: risk 11 is a direct consequence of this shape.

8. **JSON contract lacks stable identifiers.** `Cause` has only prose `title` (analyze.go:52-57); no `code`/`id`, no schema version on `Result`; `request.extended` mixes units. Why it matters: README.md:121-127 pitches CI gates and dashboards, which would have to string-match titles that change with wording edits.

9. **CI/Makefile gaps.** ci.yml runs vet, race tests, and build (good). Missing: golangci-lint or staticcheck, a gofmt check, a `go mod tidy` diff check, govulncheck, dependabot, coverage reporting, a multi-version matrix. Makefile has no `lint` target and no version ldflags; `make demo` greps test output with `sed` (Makefile:17), which breaks on any wording change. Why it matters: the deprecated `NewSimpleClientset` call would already be flagged by staticcheck.

10. **Release hygiene.** Tags v0.1.0 to v0.6.0. No CHANGELOG (release notes are auto-generated). `.krew.yaml` is deliberately frozen (CONTRIBUTING.md:74-80), but `docs/krew-index/why-pending.yaml` is a second copy that will drift. Marketing drafts (launch-post, show-hn, devto-post, launch-playbook) live in `docs/` next to engineering specs. Why it matters: none of this blocks users, but it costs maintainer attention every release.

11. **Docs drift.** README.md:57 "re-runs the scheduler's filtering logic locally" overclaims against the matrix above (roughly half the filter plugins, most partially). README.md:81-82 "computes the real skew across all domains" contradicts risk 7. README.md:87 promises the scheduler event fallback that risk 16 says may never render. README never documents cluster-wide RBAC, the 30s deadline, supported Kubernetes versions (DRA v1 only means 1.34+), or that Pending-with-node pods are skipped. CONTRIBUTING.md:19-29 layout omits dra.go, devicetaints.go, operator.go, and serialize.go. Why it matters: the misdiagnosis issue template will collect reports for cases the docs imply are handled.

## TOP 10 (ranked by value)

1. **Read scheduling gates and nominatedNodeName; stop reporting Pending-with-node pods as "no Pending pods".** Effort S. Correctness. Three small guards that remove the most embarrassing confident-wrong outputs (risks 1, 2, 20).

2. **Make DRA gather honest.** Effort S. Correctness. List claims per pod namespace, distinguish "could not read" from "absent", add the v1beta1/v1beta2 fallback that DeviceTaintRules already have, and downgrade to Info when the API is unreadable (risk 14).

3. **Replace hand-rolled predicates with `k8s.io/component-helpers`.** Effort M. Correctness. Taints, node affinity, and label selectors become scheduler-identical by construction, deleting ~200 lines and the empty-term bug; add predicates_test.go for what remains (risk 8, health 1, 5).

4. **Fix inter-pod affinity semantics.** Effort M. Correctness. Self-match exception, anchors on non-eligible nodes, namespaceSelector, and symmetric anti-affinity (needs affinity terms on PlacedPod) (risks 3-6).

5. **Volume awareness for the on-prem niche.** Effort M. Correctness plus feature. Read StorageClass bindingMode to make WFFC an Info not a Blocker, check Bound PV nodeAffinity against candidate nodes, include ephemeral volumes' PVCs (risk 12).

6. **Update NodeVerdict after every analysis and add `--nodes` to text output.** Effort S. Correctness plus usability. Makes the JSON per-node breakdown true and surfaces it where most users look (risk 11, usability 4).

7. **Scheduler event fallback chain (series.lastObservedTime, eventTime, lastTimestamp) and involvedObject.uid selector, with a test.** Effort S. Correctness. Likely restores a feature the README already advertises (risk 16).

8. **Adopt `genericclioptions.ConfigFlags` and add `--version` and `--timeout`.** Effort M. Usability. Gets `--flag=value`, impersonation, request timeout, and version stamping in one move (usability 1-3, risk 18).

9. **Complete NodeResourcesFit.** Effort S. Correctness. Add pod overhead, sum native sidecars, include ephemeral-storage, honor pod-level resources (risk 9).

10. **Group-by-cause summary for `-A` and concrete fix commands using real node/taint names.** Effort M. Usability. Turns 500 identical blocks into one line each and makes "get the fix" literal (usability 5, 8).

Just outside the list, in order: hostPort/NodePorts modeling (M, feature), topology spread nodeAffinityPolicy Honor semantics (S, correctness), and golangci-lint plus tests for args/report (S, health).
